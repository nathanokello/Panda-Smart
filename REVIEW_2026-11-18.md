Other points to settle before pitching:
- Two web apps exist. The HTML app is the complete one (lots, lot detail, events,
  corrections, users, seasons, soil, bilingual verify). The React app is partial. The
  committed `backend/.env` points verify links at React (`:5173/verify/`) while the
  README and tests assume HTML (`:5500/verify.html?token=`). Pick one.
- `Panda_Smart_Project_Overview.docx` inside the repo is the older draft
  (it lacks the "Across seasons" row and the unverified-dispute note). Replace it with `...Overview1.docx`.
- `OPEN_METEO_ENABLED=1` is set in `.env`. Its free tier is non-commercial; fine for a demo, not for a paid launch.
- Advice "confidence" is a rules score, not a probability, but the pitch promises "probabilities, not certainties".
- Rainfall "onset" is 20 mm cumulative anywhere in the last 30 days, which a month of light drizzle can trigger. Agree a proper onset rule with an agronomist.

## 2. Bugs found

Fixed (see CHANGES.md, Round 4): forged verification via events API; fail-open
cooperative scope; empty farmer verification page; 500s on bad correction id and
NaN readings; hash-chain and double-response races; watermelon lots; advice window in
the past; season mix-up on the ward dashboard; foreign plot on a plan; weather 500;
throttle crash; stale seeded rules; env-dependent tests; React sign-out, expiry,
pagination, farmer planting slots, verify page, demo credentials.

Not fixed (need a decision or are larger work):
1. Ward list totals (`/dashboard/wards/`) are not covered by the "fewer than 5 farmers" rule, so a ward with one farmer reveals that farmer's acreage and stock.
2. Agents can read the farmer's verification URL (needed until SMS exists). Consider showing it only once, at registration.
3. USSD END messages are cut at 182 characters, which can cut off the "this is a placeholder window" warning.
4. Slot rotation, scheduled checks, offline sync, SMS: not built.
5. Per-lot summary queries run per row (N+1); fine for a pilot, slow for large lists.
6. HTML app `config.js` hardcodes `http://127.0.0.1:8000`.
7. Phone numbers are normalised, not verified (no SMS code).
